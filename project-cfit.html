Work/CFIT Timetable System

Flagship · Wintec industry internship 2026

From three spreadsheets to one checked timetable.

CFIT Timetable is a full-stack scheduling platform for Wintec’s Centre for Information Technology. It imports a term’s Excel workbooks, flags scheduling conflicts, suggests fixes, and keeps every change as a Version you can restore.

01 The problem

Clashes hid in three workbooks.

Every term began as three Excel workbooks: the rooms, the Modules and their Tutors, and the timetable itself. Keeping them in step meant checking rows against each other by hand, every change had to be made in several places, and a double-booked room could sit unnoticed until the first week of teaching.

The CFIT team needed one place that checks the data, shows it clearly and keeps a record of every change, without forcing them to give up Excel, which the rest of the institution still uses.

02 What I built

Most of the code, across the whole stack.

I led development across the React and TypeScript client, Spring Boot API, PostgreSQL schema, Excel import/export and automated tests, working with another contributor and the CFIT team as the client.

  • Import and validation: every workbook row is checked before anything is saved.
  • Four views of one timetable: Day, Week, Stage and the Activity Inspector.
  • Clash detection and suggested fixes, including coordinated fixes that move several sessions together.
  • Direct editing: drag, split and merge, each checked again before it is applied.
  • Versions: every change is saved as a Version that can be compared and restored.
  • Output: print-ready PDFs and an Excel export that round-trips back into the app.

Real application · Fictional demonstration data.

03 The workspace

One timetable, four ways to read it.

Day view puts one column per Stage, so a room clash is visible at a glance. Week view shows every Stage from Monday to Friday, Stage view follows one cohort through the week, and the Activity Inspector shows when, where and who for any session.

04 Import & validation

Every row checked. Nothing saved until you confirm.

Import reads the term’s workbooks and checks every row before anything reaches the database. In the demonstration term, 99 source rows are checked with 0 errors; problem rows would be listed with the reason and the cell they came from.

05 Clashes & fixes

Some clashes have no simple fix.

Validation flags double-booked rooms and staff, rooms that are too small and staff who are unavailable. For each finding, Suggest fixes proposes changes that solve the problem without creating a new one.

In the demonstration term, import gives Version 1 with two clashes. The Wednesday clash has a simple fix: one session moves to a free room, saved as Version 2. The Monday clash is the hard case: a masterclass that cannot move shares a room with a regular session, so the fix moves three sessions together. The preview shows each move, with the old slot dashed, and nothing is saved until Apply. Apply saves Version 3 with 0 findings.

06 Editing

Drag. Split. Merge, checked before it is applied.

Sessions can be reshaped directly on the grid. Every edit is previewed and validated before it is applied: a split keeps the same Tutor and room, and a merge checks that the combined class still fits the room.

07 Version history

Every change is a Version you can restore.

History lists each saved Version with its changes, so a timetabler can see exactly what changed, when, and go back if needed.

08 PDF & Excel

Back out to paper and to Excel.

The app makes print-ready A4 PDFs by day, and exports the exact saved Version as a workbook that can be imported again. At the feature freeze, the Excel round trip came back with nothing missing, added or different.

09 Engineering

A modular monolith with tests at every layer.

A React client talks to a Spring Boot API organised as a modular monolith, backed by PostgreSQL with versioned migrations. Every push to main runs unit tests, integration tests and five browser test groups on GitHub Actions.

10 Outcome

One workflow from import to export.

The system gives the CFIT team one place that checks every change as it is made, instead of cross-checking three workbooks by hand, so a clash is found when it is created rather than in the first week of teaching.
